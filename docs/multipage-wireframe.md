# ワイヤーフレーム — 複数ページ化（Issue #14）

対象: 現行1ページLPを6つの公開ページへ分割する。`/guide/` は対象外（既存のまま noindex,nofollow・公開ナビ非掲載を継続）。

## 公開ページ構成

| URL | 役割 | 検索/ユーザー意図 |
|---|---|---|
| `/` | トップ（要約＋主要CTA） | サービス全体を素早く理解し、詳細ページまたは相談へ進む |
| `/service/` | サービス内容 | 「何をしてもらえるのか」を具体的に知りたい |
| `/price/` | 料金 | 費用感・見積もりの仕組みを知りたい |
| `/flow/` | 制作・公開後の流れ | 依頼してから公開まで、公開後の運用がどう進むか知りたい |
| `/demos/` | 制作デモ一覧（ハブ） | 実際の仕上がり品質を見たい（既存3デモへの入口） |
| `/faq/` | よくある質問 | 個別の疑問・不安を解消したい |

既存デモURL（`/demos/salon/`, `/demos/cafe/`, `/demos/reform/`）は変更しない。`/demos/`はそれらの親ハブとして新設する。

## 共通レイアウト（全公開ページ）

1. `<a class="skip-link">` 本文へスキップ
2. `header.site-header`: ロゴ（`/`へリンク）+ ナビトグル（モバイル）+ `nav#site-nav`（トップ/サービス/料金/流れ/デモ/FAQの6リンク、現在地に`aria-current="page"`）+ ヘッダーCTA「無料相談する」（トップは`#contact`、他ページは`/#contact`）
3. `main#main`
   - パンくずリスト（トップ以外。`nav[aria-label="パンくずリスト"]`、視覚表示＋`BreadcrumbList`構造化データ）
   - ページ固有コンテンツ（下記）
   - ページ末尾に他詳細ページ・相談への内部リンク（CTA帯）
4. `footer.site-footer`: サイト名、コピーライト、簡易サイト内リンク（6公開ページ、`/guide/`は含めない）

## `/`（トップ）— 要約＋CTAに整理

既存1ページ構成から、各詳細ページへ切り出した内容は要約2〜3文＋「詳しく見る」リンクへ圧縮する。トップに残す/圧縮する内容:

1. Hero（現状維持）
2. こんな悩み（現状維持、短いリストのため圧縮不要）
3. 選ばれる理由（3つ、現状維持）
4. はじめかた3ステップ（要約表示のまま維持し、末尾に「→ 制作・公開後の流れを見る」で`/flow/`へ）
5. 公開後の更新デモ（チャットふきだしUI、現状維持。サービスの中核差別化要素のため圧縮しない）
6. サービス要約（NEW・圧縮）: 「できること」「活用シーン」「普通のホームページ制作との違い」を短い1ブロックに要約し、「→ サービス内容を詳しく見る」で`/service/`へ。既存の全文（機能一覧グリッド・活用シーングリッド・比較表）はトップから削除し`/service/`へ移設。
7. デモ紹介（現状の3カードは維持。既存デモURLへの直接導線は価値が高いため圧縮しない）＋「→ 制作デモ一覧を見る」で`/demos/`へ
8. 料金要約（NEW・圧縮）: 個別見積もりである旨と2区分（初期制作費/月額運用費）を1〜2文に要約し、「→ 料金を詳しく見る」で`/price/`へ。既存の`pricing-blocks`詳細説明は`/price/`へ移設。
9. FAQ要約（既存8問から3〜4問へ絞る）＋「→ よくある質問をすべて見る」で`/faq/`へ
10. 最終CTA（現状維持）
11. お問い合わせ（`#contact`、現状維持。問い合わせ方式はIssue #11のため変更しない）

## `/flow/`

1. Hero（H1「制作・公開後の流れ」+ リード文）

## `/demos/`（ハブ）

3. デモの見方（業種ごとの構成方針を短く説明）
4. CTA（自分の業種での制作を相談する導線として`/service/`・`/#contact`）

## `/faq/`

1. Hero（H1「よくある質問」+ リード文）
2. カテゴリ別FAQ（H2で「サービスについて」「料金について」「制作・運用について」「お申し込みについて」に分割し、既存8問+加筆分を再配置。`<details>/<summary>`を維持）
3. CTA（`/#contact`）

## 見出し・ランドマーク方針

- 各ページのH1は1つのみ。以降H2→H3の順序を守る。
- ランドマークは`header`, `nav[aria-label]`（サイトナビ・パンくず）, `main`, `section[aria-labelledby]`, `footer`。
- パンくずは視覚的にもリンクとして機能させ、JS不要。

## モバイル/デスクトップ差分方針

既存LPと同一のブレークポイント方針を踏襲する（320〜430px 1カラム、600px〜 2カラムグリッド、1024px〜 デスクトップナビ・比較表通常表示）。
